# Weight provenance and DIMER hosting

- Upstream: `docling-project/SmolDocling-256M-preview`
- Immutable revision: `ce51f56c4ebe36e0b1c3a55f67b261ba22a50bf8` (the Hub's `main` resolved to this commit on 2026-09-14)
- Weight format: SafeTensors (`model.safetensors`, 513,028,808 bytes, bfloat16 tensors); the upstream repository also hosts an `onnx/` export, which this pipeline neither lists nor loads, and no pickle checkpoint.
- Manifest: `weights/smoldocling-256m-preview/dimer-base-manifest.json` (13 files: `README.md`, `added_tokens.json`, `chat_template.json`, `config.json`, `generation_config.json`, `merges.txt`, `model.safetensors`, `preprocessor_config.json`, `processor_config.json`, `special_tokens_map.json`, `tokenizer.json`, `tokenizer_config.json`, `vocab.json`; 517,896,538 bytes total, per-file SHA-256)
- Upstream weight license: **CDLA-Permissive-2.0** per the checkpoint `README.md` front matter (`license: cdla-permissive-2.0`) and the Hub's licence tag. The same README's "Model Summary" section says "License: Apache 2.0"; the front matter is the machine-readable declaration and the one this repository records. Both are permissive, allow redistribution and commercial use, and require the licence text to travel with the weights; the discrepancy is recorded in `MODEL_CARD.md` and should be resolved with the upstream maintainers before any use where the distinction matters.
- DIMER hosting: CDLA-Permissive-2.0 permits use, modification and redistribution of the "Data" (here the weights) with the licence text; it imposes no obligation on results produced with the data. The Git repository does not vendor the checkpoint (`weights/**/*.safetensors` is git-ignored); DIMER may mirror the pinned snapshot in its model store under the upstream licence.
- Fresh clone: `stage_missing_files(allow_download=True)` fetches only the manifest-listed files absent on disk, at the pinned revision, into the snapshot directory; `verify_snapshot()` then checks every file before any load. `weights/**` is marked `-text` in `.gitattributes` so Windows `core.autocrlf` cannot rewrite the committed small files and break their digests.
- Loader trust boundary: Transformers `AutoModelForImageTextToText` (`Idefics3ForConditionalGeneration`) / `AutoProcessor` with `trust_remote_code=False`, `local_files_only=True` from the verified directory; the processor and chat template come from the same snapshot; nothing is fetched at construction (the smoke run loaded with `HF_HUB_OFFLINE=1`). The model is loaded in float32 on CPU and bfloat16 (the checkpoint's stored dtype) on CUDA.

## Adaptation artifacts and the sample corpus

- Dtype: the pipeline loads the bfloat16 checkpoint in float32 on every device (the adapter is trained in float32 and overlays without a cast; the inference-only card was measured with float32 on CPU and shipped bfloat16 on CUDA).
- Adapter artifacts: `save_artifact` writes the trained tensors (the last eight SmolLM2 decoder layers and the final norm, 73 tensors, about 113 MB in float32) as `adapter.safetensors` beside a `manifest.json` (`org.valcorza.smoldocling-256m-preview.adapter.v1`) naming the base model id and revision, the base `model.safetensors` SHA-256, the tensor names, the file size and SHA-256, the instruction and the DocTags line target the adapter was trained on, the training configuration and the epoch history. `from_artifact` re-verifies the base snapshot and checks the manifest, the digest and the exact tensor set before deserialising; an adapter is derived from the lines it was trained on and is not redistributed by this repository.
- Adaptation sample: `Teklia/Belfort-line` (MIT), parquet-conversion revision `c4a74bbd39f2df314752e7e6026649a39d365cbb`, `default/test/0000.parquet` row groups 0–7 (800 lines, about 44 MB) read over HTTPS range requests, each row group pinned by SHA-256 and byte total in `samples.py`; cached git-ignored under `weights/belfort/`, never vendored.
